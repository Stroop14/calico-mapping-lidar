Silver King Mine

You have a new LiDAR scan. This is how it becomes a walk.

The scanner handed you LAS files, or LAZ files, which are the same points in a compressed file. Often there are several, and they do not yet sit in one tunnel. Part 1 turns them into one LAS file without moving the measured points and without throwing away a cart, a timber, or a person. Part 2 paints ground, wall, and ceiling so the shape reads, builds the walk, and gives you a folder students open on a phone or a computer. The Silver King walk is one finished result of this sequence. Your files go through the same two parts.

If you already have one LAS file and the scans already share one coordinate system, start at Part 2.

Part 1. Make one LAS file from the scanner files

CloudCompare is the program for this part. The points you keep are a subset of the points the scanner measured. This part does not stretch them, and it does not recolor them.

Download CloudCompare

  1. Install CloudCompare.

    CloudCompare is the free program that lines the scans up. Download it from cloudcompare.org, install it, and open it.

  2. Open the scan files.

    1. In CloudCompare, click File, then Open.
    2. Select every LAS or LAZ file from this scan. Hold Ctrl to select more than one. Click Open. LAZ is the compressed copy of the same points. CloudCompare opens it. The walk program in Part 2 does not, so step 8 saves LAS.
    3. Each file becomes one row in the DB Tree, the list on the left. The checkbox on a row shows or hides that cloud. Click the name to select it. A selected name is highlighted.
    4. The mouse in the 3D view: hold the left button and drag to rotate. Hold the right button and drag to slide the view. Roll the wheel to zoom. This is the normal mouse. Step 6 changes it while a polygon is being drawn.

  3. See whether the scans already share one coordinate system.

    1. Check the box on every scan so all of them are drawn. CloudCompare gives each one a different color when the file has no color.
    2. Rotate and zoom until you can see the whole set.
    3. If the walls of both walks occupy the same place, and the two colors are mixed on the same wall, they already share a coordinate system. Go to step 6.
    4. If you see two separate tunnels, or one tunnel floating away from the other, they do not share a coordinate system. Do step 4, then step 5, then step 6.

  4. Line the shifted scan up on the overlap.

    1. In the DB Tree, click the name of the scan that is in the wrong place.
    2. Hold Ctrl and click the name of the scan that should stay put. Both names are highlighted.
    3. Click Tools, then Registration, then Align (point pairs picking).
    4. The first window assigns roles. Aligned is the cloud that will move. Reference is the cloud that will not move. Set the two drop-downs. If they are reversed, click Swap. Click OK.
    5. Both clouds are now in one view, and a window opens at the upper right. It has an Aligned table, a Reference table, a checkbox for each cloud, an align button, a reset button, a green check mark, and a red X.
    6. Uncheck Reference so only the cloud that moves is visible.
    7. Left-click a spot that also exists in the other scan: a corner, the end of a timber, a rock edge, a rail. A marker whose name starts with A is drawn, and a row is added to the Aligned table.
    8. Left-click at least three more spots on that same cloud, spread along the overlap. Four pairs hold better than three. The row order is the pair order. Write the order down if you will not remember it: first spot, second spot, third spot, fourth spot.
    9. Uncheck Aligned. Check Reference.
    10. Left-click those same physical spots, in the same order. The first click on this cloud must be the same place as the first A marker. Markers whose names start with R are added to the Reference table. The two tables need the same number of rows.
    11. Check both clouds.
    12. Click align. The moving cloud shifts. The window shows an RMS, the leftover mismatch, and an error on each row.
    13. If one row’s error is much larger than the others, click the X on that row in both tables, pick that pair again, and click align again.
    14. Leave fixed scale checked. Unchecking it rescales one scan. These files came from the same kind of instrument.
    15. Click the green check mark to keep the move. A report window opens. Close it. Clicking the red X throws the move away. Reset puts the moving cloud back where it was before this tool.
    16. Rotate the result. If the walls now occupy the same place, go to step 5. If they are close and still separated by a small gap, do the next three clicks.
    17. Click Tools, then Registration, then Fine registration (ICP).
    18. In that window, Data is the cloud that moves. CloudCompare draws it red. Model is the cloud that stays. CloudCompare draws it yellow. Click Swap if red and yellow are reversed.
    19. Set Final overlap to the percentage of the moving scan that covers the same tunnel as the scan that stays. When about half of the moving scan overlaps the other, type 50. The value already in the box is 100. At 100, CloudCompare treats every point of the moving scan as part of the same object, and a scan that only shares a section of the tunnel is shifted off that section.
    20. Leave Adjust scale unchecked. Click OK. Wait until the red cloud stops moving.

  5. Merge the two scans into one cloud.

    1. In the DB Tree, click one scan’s name.
    2. Hold Ctrl and click the other scan’s name. Both are highlighted.
    3. Click Edit, then Merge.
    4. A new row appears in the DB Tree. That row is the combined cloud. The two original scans are still in the list.
    5. Uncheck the two originals. Leave the new cloud checked. Steps 6, 7, and 8 use the new cloud. The originals stay on disk as the files you opened.

  6. Delete the points that are far from the tunnel.

    The command is Edit, then Segment. It draws a polygon on the screen and then deletes the points on one side of that polygon. A minecart and a person stay in the result because you include them inside the polygon.

    Tools, then Clean, then SOR filter is a different command. SOR deletes points whose distance to their neighbors is larger than the distances in the rest of the cloud. A person and a minecart are sparse next to a wall, so SOR removes them. This step does not use SOR.

    1. In the DB Tree, click the merged cloud so its name is highlighted. The original scans stay unchecked.
    2. Click Edit, then Segment. A toolbar is added at the upper right of the 3D view.
    3. Press the Space bar. The Pause segmentation button is down. Shortcut: Space. While that button is down, the mouse is the normal mouse: left button rotates, right button slides the view, wheel zooms. Turn the cloud until the tunnel is one group and the stray points are visibly far from it.
    4. Press the Space bar again. Pause is off. Left-clicks now add corners of a polygon. The right button no longer slides the view.
    5. The toolbar’s selection mode should be polygonal. The tooltip on that button says “Polygonal selection”. If it says rectangular, click the arrow next to it and choose polygonal, or press Tab.
    6. Left-click a corner out past the tunnel, with the walls, the ground, the ceiling, the minecart, and any person inside the shape you are drawing. Left-click the next corner. Repeat until the polygon surrounds the whole tunnel. Between clicks, the current edge follows the mouse.
    7. Right-click once. That closes the polygon. The right-click does not add a corner.
    8. Click the toolbar button whose tooltip is “Segment Inside”. The second line of the tooltip says “keep points inside”. Shortcut: I. Points outside the polygon vanish from the view. They are hidden. They are not deleted yet. The tool returns to pause, so the left button rotates again.
    9. Rotate the cloud. Look at both ends, the cart, and the people. If something that belongs in the tunnel is missing, click the button whose tooltip is “Reset segmentation” (“Clear segmentation”). The hidden points return. Press Space to leave pause, and draw a wider polygon.
    10. When the view shows the tunnel and the things in it, and the far points are hidden, click the trash-can button. The tooltip is “Confirm and delete hidden points”. Shortcut: Delete. CloudCompare deletes the hidden points and leaves one cloud.
    11. Escape cancels the tool and deletes nothing. Enter confirms a split into two clouds and does not delete the hidden points. For one cloud with the far points removed, use the trash-can button.

  7. Thin the cloud.

    1. Click the cloud that remains after step 6.
    2. Hover a point in the 3D view and read the coordinates in the status bar at the bottom. If those numbers are in the tens or hundreds, the file is in meters. If they are in the tens of thousands, the file is in millimeters.
    3. Click Edit, then Subsample.
    4. Set the method to Spatial. Random, Random (%), and Octree are the other methods in that list. Spatial is the method with a minimum distance between kept points.
    5. In the minimum-distance box, type 0.02 if the file is in meters. That is 2 centimeters. Type 20 if the file is in millimeters. A short drift comes out around a million points.
    6. Click OK. CloudCompare makes a new cloud and unchecks the one you subsampled. The new cloud is the one to save. The points that remain are a subset of the old points. They are not moved.

    The Silver King file used 0.0125 meters, which is 1.25 centimeters, and kept 13,657,307 points. Use 0.02 unless the machine can hold the finer cloud. The walk program in Part 2 thins again to about 2 centimeters and about 1.5 million points.

  8. Save a LAS file.

    1. Click the new, subsampled cloud so its name is highlighted.
    2. Click File, then Save.
    3. At the bottom of the save window, open the file-type list. Choose “LAS cloud (*.las)”. BIN is CloudCompare’s own format. LAZ is compressed. The walk program in Part 2 opens LAS. It does not open LAZ or BIN.
    4. Choose a folder and a file name. Click Save.
    5. If a second window asks for a LAS version, point format, or scale, leave the values that are already filled in and click OK.

    If the scanner gave you LAZ, open that LAZ in CloudCompare and save it again with the file type set to LAS cloud.

Part 2. Paint the surfaces and publish the walk

The LAS file from Part 1 is the measurement. This part does not move those points. It gives the ground, the wall, and the ceiling three different colors so a student can read the shape of the drift, puts a headlamp and a little fog on the cloud so the rock reads as a surface, and writes a folder. That folder is the site.

A handheld scanner often records no color. The colors on the walk are paint. Say that next to the walk when you publish it. A black opening over a shaft, or at the end of an adit, is a place the scanner did not return points. It is not a black rock.

The path Play follows runs down the middle of the points so a student can travel the drift. It is a viewing path. It is not a surveyed centerline. Distances between the points are the scan. On the page you give students, write the spacing you kept: 0.02 m, or 0.0125 m if you used the finer setting below.

Download the walk program

  1. Unzip mine-walk-program.zip. The folder contains HOW.txt, tools/mine-walk/make_walk.py, tools/mine-walk/viewer.html, and lib/three.min.js.
  2. Install Python from python.org if the computer does not have it. On the Windows installer, check Add python.exe to PATH.
  3. Open a terminal in the unzipped folder. On Windows, click the folder address bar, type cmd, and press Enter. On a Mac, open Terminal, type cd, then a space, and drag the folder into the window.
  4. Run pip install numpy pillow. NumPy holds the list of point coordinates. Pillow opens the photograph. They are not part of the scan.
  5. Copy the LAS file from Part 1 into that folder. Copy one photograph of the tunnel into the same folder. The photograph is only there to supply three colors.
  6. Run the command below. Replace the file names with the real names. On Windows, if python3 is not found, use python.
python3 tools/mine-walk/make_walk.py yourscan.las --photos yourphoto.jpg --out site

The photograph is split into three bands. The bottom band is the ground color. The middle band is the wall color. The top band is the ceiling color.

If the ground and the wall are two separate photographs:

python3 tools/mine-walk/make_walk.py yourscan.las --floor ground.jpg --wall wall.jpg --out site

The default spacing is 0.02 meters, and the program keeps at most 1,500,000 points so a phone can open the same cloud as a desktop. For 1.25 centimeters, put --cell 0.0125 before --out site. --max-points 0 keeps every point that remains after that spacing. The points that remain are still the measured points. They are not moved to new positions.

  1. Run these two commands, then open the address in a browser.
cd site
python3 -m http.server 8000

Open http://localhost:8000/.

  1. Press Play and walk the drift once before you publish it. The orange dot is the first point of the viewing path. The green dot is the last. Reverse swaps the direction. Lamp turns the headlamp off and on. Look at both ends, the carts, and the timbers. If something that belongs in the tunnel is missing, go back to Part 1, step 6, and draw a wider polygon. If the walls are doubled, the alignment in Part 1, step 4, is still off.
  2. Students move the same way you do. W walks forward, S walks back, A steps left, D steps right. Hold Shift to go faster. Drag with the left mouse button to turn. Click once and the mouse looks for you; press Esc to release it. Drag with the right mouse button to slide sideways and up. The wheel moves in and out. On a phone, drag the left side of the screen to walk and the right side to look. Press [ to make the dots smaller and ] to make them larger. The phone draws larger dots so a thinned wall still reads as a surface. The desktop draws smaller dots so the detail shows. Both use the same points.
  3. Upload the site folder to a web host. Send students that one address. A phone and a computer open the same page and the same cloud.

To try Part 2 before your own LAS is ready, unzip silver-king-combined.las.zip and use the LAS file inside. It is the Silver King merge at 1.25 cm, 13,657,307 points. The program will thin it again unless you pass --cell 0.0125 --max-points 0.

The same sequence, for Cursor with Grok 4.7 or Opus 5.5. Put the LAS file and the photograph in the folder, and paste this:

Build a walk-through of one mine LiDAR scan as one web page. Phone and desktop open the same page and the same cloud. Desktop dots are smaller. Phone dots are larger, so a thinned wall still reads as a surface.

CloudCompare, in this order:
1. File, Open. Left-drag rotates, right-drag pans, the wheel zooms.
2. If the tunnels do not occupy the same space: Tools, Registration, Align (point pairs picking). Aligned moves. Reference stays. Pick at least four of the same spots, in the same order, on each cloud. Click align, then the green check. Leave fixed scale checked. If a gap remains: Tools, Registration, Fine registration (ICP). Data is red and moves. Model is yellow and stays. Set Final overlap to the percent of the moving scan that covers the other. Leave Adjust scale unchecked.
3. Edit, Merge. Use the new cloud.
4. Edit, Segment. Space pauses so the view can rotate. Space again to draw. Left-click a polygon around the tunnel, including the walls, the ground, the ceiling, a minecart, and any person. Right-click closes the polygon. Click Segment Inside. Click Confirm and delete hidden points. Do not use Tools, Clean, SOR filter. SOR removes sparse objects such as a person or a cart.
5. Edit, Subsample. Method: Spatial. Minimum distance 0.02 if the coordinates are meters, or 20 if they are millimeters. File, Save. File type: LAS cloud (*.las).

Then:
6. One photograph sets three colors: bottom is ground, middle is wall, top is ceiling.
7. Build one web page from that LAS. The camera starts inside the tunnel. Store a path down the middle. Play follows it. The first point is orange. The last point is green.
8. W A S D moves. Shift is faster. Left drag looks. Right drag slides. The wheel moves in and out. On a phone, the left side walks and the right side looks.
9. The result is a folder that can be hosted. The scan is not uploaded.
